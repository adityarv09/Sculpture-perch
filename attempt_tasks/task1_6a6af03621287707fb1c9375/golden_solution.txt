TASK 1 - DETERMINISTIC GOLDEN ANSWER
ZM3D ("Puzzles vs Zombies") store-submission readiness / go-no-go

====================================================================
OVERALL CALL: NO-GO
====================================================================

The build is not shippable. The checklist ("Release Checklist & Store
Submission", owner Vincent Parker, QA) makes QA sign-off a hard gate,
and there is no QA sign-off on record for this build anywhere in the
systems. On top of that, the two items that have burned the team before,
the update path from the last two shipped versions and the splash /
loading experience, both have live, unresolved bugs. Any one of these is
enough to hold the release. Together they make the call an easy no-go.

Top blockers (these are what stop the release):
1. No QA sign-off exists for this build. QA sign-off is a hard gate, so
   no sign-off means it is not shippable.
2. Update path from N-1 and N-2 is not verified and there are open
   progression / save-integrity bugs, which is the exact class of
   failure the June 2025 progression wipe hardened against.
3. The splash / loading path has open regressions, which is the exact
   class of failure ENG-2346 and ENG-2343 hardened against.

====================================================================
HOW THE GATE WORKS (method)
====================================================================

The checklist itself is the gate. Every item has to be ticked AND QA has
to sign off before a build can go to the App Store or Google Play. Two
rules override everything else:
 - QA sign-off is a hard gate. No sign-off means not shippable, full stop.
 - The update path must be tested from the last two shipped versions
   (N-1 and N-2), not just a clean install. A fresh-install-only pass
   does not clear this gate (this is the June 2025 progression wipe,
   which only reproduced on the update path).

Each item below is judged against the actual build using real evidence
from Confluence, Linear, GitHub and Slack, and marked PASS, FAIL,
BLOCKED or NEEDS-INFO. Where nothing in the systems can prove an item, it
is marked NEEDS-INFO rather than assumed to be fine.

Source of truth for the checklist:
 - Confluence page "Release Checklist & Store Submission" (space OPS),
   including the Build & QA section, the Store metadata & compliance
   section, and the Lessons from incidents table.

BUILD & QA SECTION
====================================================================

Item 1. Full manual regression green on real iOS and Android hardware,
QA sign-off is a hard gate.
 Status: FAIL (hard gate not satisfied)
 Evidence: The checklist names QA sign-off as a hard gate. There is no QA
 sign-off recorded for this build anywhere in the systems. This was
 checked across all four places a sign-off could live: Gmail (the only
 "sign-off" / "go-no-go" emails are about fundraising and legal
 documents, none is a QA sign-off for this build), Slack (the only
 sign-off threads are fundraising, none is a QA build sign-off), the
 submission-blockers channel (no signed pass), Confluence (the checklist
 is the gate and the QA Regression Runbook is the process, but no signed
 pass for this build exists), and Linear (no signed QA pass tied to this
 build). With the gate owner being QA and no sign-off on record, this
 item cannot be treated as satisfied.

Item 2. Update path verified from N-1 and N-2, level / coins / unlocks
survive the update, no save or progression loss.
 Status: BLOCKED
 Evidence: There is no evidence the update path was tested from the last
 two shipped builds, and there are open bugs that directly threaten
 progression and save integrity on update / re-entry, for example the
 quest-chest progression reset after reinstall with a signed-in account
 (ENG-2114, open) and the sign-in account synchronization / load-prior-
 data problems (ENG-2073, ENG-2280, ENG-2281, open). This is the same
 failure mode as the June 2025 progression wipe, which only showed up on
 the update path. On top of that, there is no authoritative release or
 version log in the systems available here (no GitHub releases and no
 release-log page), so the two shipped versions this update path must be
 tested from cannot even be pinned to specific version numbers from the
 tools. That the last two shipped builds are not clearly identifiable is
 itself part of why this gate is not verifiable and stays BLOCKED. Until
 the N-1 and N-2 update path is confirmed clean against the actual last
 two shipped builds, this item blocks the release.

Item 3. Splash and loading screen watched all the way to gameplay on a
throttled connection and with the cache cleared, no stall.
 Status: FAIL
 Evidence: The historical splash incidents were hardened and closed
 (ENG-2346 downloading fonts made the game look frozen, Done, and
 ENG-2343 splash / loading resolution, Done). However there are open
 regressions in the same area for this build: the game getting stuck at
 the splash screen after sign-in (ENG-2363, In Progress) and the black
 screen at start taking too long (ZOM-608, in a regression state). The
 splash-to-gameplay path is not clean, so this fails.

Item 4. Live quest config, if touched, has passed QA and a canary,
nothing pushed straight to the live quest server.
 Status: NEEDS-INFO
 Evidence: It cannot be confirmed from the systems whether the live
 quest config was changed for this build, or whether a canary plus QA
 was run before anything reached the live quest server. The Quest System
 Design and Incident Postmortem (Confluence) is why this item exists.
 What is missing: confirmation of whether quest config changed for this
 build and, if so, the canary and QA evidence.

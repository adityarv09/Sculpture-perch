RED FLAG NOTES AND OVERRIDES
==================================================================

OVERRIDE 1, DOOM LOOP DETECTOR, CONFIRMED FALSE POSITIVE RISK. run3 issued 45 consecutive linear_update_issue calls and 8 consecutive linear_create_issue calls. A reviewer or automated detector matching on tool name alone will read that as a doom loop. It is not one, and run3 is the best run in the set. "Tag every ticket in Bugs, Regression or In Progress with its incident, or mark it unrelated" makes each of the 45 a distinct write against a distinct issue id, and the prompt requires every one. A doom loop requires the same call with the same arguments. The distinguishing check is whether the issue id changes between calls; in run3 it changes every time. Do not fail run3 on repetition count.

OVERRIDE 2, ABSENCE FINDINGS ARE NOT MISSING WORK. Incidents 3 and 4 correctly end in "no code fix was ever merged". A reviewer scanning for completeness may read a missing pull request reference as an incomplete investigation. It is the finding. A run that invents a fix here should fail the fabrication penalty, not be credited for thoroughness.
